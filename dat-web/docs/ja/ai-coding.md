# AI バイブコーディング

現在のプロジェクトと実現したい動作を AI に伝えると、DAT を統合しやすくなります。以下の例では、プロジェクトに合わせて URL と環境変数名だけを変更してください。

## シンプルな実装

基本構造をすばやく作成したいときは、このプロンプトを使用します。

```text
Kotlin と Spring Boot を使用しています。
Spring Security に DAT 認証を追加してください。

まず https://dat.saro.me/llms.txt を読み、DAT 仕様と公式ライブラリのドキュメントを確認してください。

Authorization ヘッダーの Bearer トークンを検証し、認証に成功したらユーザー情報を SecurityContext に格納してください。

このサーバーは DAT を発行せず、検証のみを行います。DAT CMS から検証専用証明書を受け取る必要があります。

まずプロジェクト内で CMS サーバーの URL とトークン設定を探してください。見つからない場合は私に確認し、値を作り上げないでください。

公式の Java/Kotlin DAT ライブラリを使用し、既存のプロジェクト構成とコーディングスタイルに従ってください。
```

## 詳細な実装

認証フローとエラー処理を正確に指定したいときは、このプロンプトを使用します。

```text
このプロジェクトは Kotlin、Spring Boot、Spring Security を使用しています。
現在のセキュリティ設定を確認してから、DAT 認証を追加してください。

まず https://dat.saro.me/llms.txt を読み、DAT 仕様、証明書の同期、公式ライブラリ API を確認してください。

次の要件を実装してください。

- Authorization: Bearer ヘッダーから DAT を読み取る。
- DAT がなければ匿名リクエストとして続行する。
- DAT が無効または失効している場合は 401 を返す。
- 検証に成功したら、ユーザー ID と権限を SecurityContext に格納する。
- plain からは公開しても安全な値のみを読み取る。
- ユーザー ID と権限は検証済みの secure データから読み取る。
- このサーバーは検証専用なので、DAT CMS の検証専用証明書を使用する。
- CMS URL とトークンは環境変数から読み取る。
- 起動時に証明書の同期に失敗した場合は、アプリケーションの起動も失敗させる。
- 実行中は証明書を自動更新し、終了時にマネージャーを閉じる。
- エラーメッセージではなく DAT エラーコードで失敗原因を区別する。
- 元の DAT、CMS トークン、個人データをログに記録しない。

まずプロジェクトの Spring Security 設定とユーザー/権限モデルを調べてください。
CMS URL、トークン環墉数、secure データ形式が不明な場合は、実装前に確認してください。
公式 Java/Kotlin DAT ライブラリの public API だけを使用してください。

コードを編集する前に、認証フローと変更するファイルを簡潔に説明してください。
```

## どの例を選べばよいですか？

- まず動作するコードが必要なら、**シンプルな実装**を使用します。
- 本番環境向けの認証フローが必要なら、**詳細な実装**を使用します。

AI から質問されたら、まず CMS URL、トークンを保持する環境変数、`secure` に保存するユーザー情報を提示してください。
