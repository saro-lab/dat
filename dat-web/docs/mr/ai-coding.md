# AI वाइब कोडिंग

AI ला सध्याचा प्रकल्प आणि हवे असलेले वर्तन सांगितल्यास DAT लागू करणे सोपे होते. खालील उदाहरणांमधील पत्ता आणि environment variable ची नावे तुमच्या प्रकल्पानुसार बदला.

## सोपी अंमलबजावणी

मूळ रचना पटकन तयार करायची असल्यास ही विनंती वापरा.

```text
मी Kotlin आणि Spring Boot वापरत आहे.
Spring Security मध्ये DAT प्रमाणीकरण जोड.

प्रथम https://dat.saro.me/llms.txt वाच आणि
DAT तपशील व अधिकृत लायब्ररीचा वापर तपास.

Authorization हेडरमधील Bearer टोकन पडताळ आणि
प्रमाणीकरण यशस्वी झाल्यास वापरकर्त्याची माहिती SecurityContext मध्ये ठेव.

हा सर्व्हर DAT जारी करत नाही, केवळ पडताळतो.
DAT CMS मधून केवळ-पडताळणी प्रमाणपत्र घ्यायचे आहे.

आधी प्रकल्पात CMS सर्व्हरचा पत्ता आणि टोकन सेटिंग्ज शोध;
सापडले नाहीत तर मला विचार. मनाने मूल्ये बनवू नको.

अधिकृत Java/Kotlin DAT लायब्ररी वापर आणि
विद्यमान प्रकल्परचना व कोडिंग शैलीशी जुळेल अशी अंमलबजावणी कर.
```

## सविस्तर अंमलबजावणी

प्रमाणीकरण पद्धत आणि त्रुटी हाताळणी नेमकी ठरवायची असल्यास ही विनंती वापरा.

```text
हा Kotlin, Spring Boot आणि Spring Security वापरणारा प्रकल्प आहे.
सध्याची सुरक्षा सेटिंग्ज तपासल्यानंतर DAT प्रमाणीकरण जोड.

प्रथम https://dat.saro.me/llms.txt वाच आणि
DAT तपशील, प्रमाणपत्र समकालन पद्धत व अधिकृत लायब्ररी API तपास.

अंमलबजावणीच्या अटी पुढीलप्रमाणे.

- Authorization: Bearer हेडरमधून DAT वाच.
- DAT नसल्यास निनावी विनंती म्हणून पुढे चालू ठेव.
- DAT चुकीचा किंवा कालबाह्य असल्यास 401 प्रतिसाद दे.
- पडताळणी यशस्वी झाल्यास वापरकर्ता ID आणि अधिकार SecurityContext मध्ये ठेव.
- जी मूल्ये सार्वजनिक होऊ शकतात तीच plain मधून वाच.
- वापरकर्ता ID आणि अधिकार पडताळलेल्या secure डेटामधून वाच.
- हा सर्व्हर केवळ पडताळतो, म्हणून DAT CMS चे verify-only प्रमाणपत्र वापर.
- CMS पत्ता आणि टोकन environment variables मधून घे.
- सुरुवातीला प्रमाणपत्र समकालन अयशस्वी झाल्यास अॅप्लिकेशन सुरू होऊ देऊ नको.
- चालू असताना प्रमाणपत्रे स्वयंचलितपणे अद्यतन कर आणि बंद होताना मॅनेजर बंद कर.
- अपयशाचे कारण त्रुटी संदेशाने नव्हे, DAT त्रुटी कोडने वेगळे कर.
- लॉगमध्ये मूळ DAT, CMS टोकन किंवा वैयक्तिक माहिती ठेवू नको.

आधी प्रकल्पाची Spring Security सेटिंग्ज आणि वापरकर्ता-अधिकार रचना तपास.
CMS पत्ता, टोकन environment variables किंवा secure डेटा स्वरूप समजत नसेल तर अंमलबजावणीपूर्वी विचार.
अधिकृत Java/Kotlin DAT लायब्ररीचा केवळ public API वापर.

कोड बदलण्यापूर्वी प्रमाणीकरण प्रवाह आणि बदलणारी फाइल्स थोडक्यात समजावून सांग.
```

## कोणते उदाहरण निवडावे?

- प्रथम चालणारा कोड बनवायचा असेल तर **सोपी अंमलबजावणी** वापरा.
- उत्पादन वातावरणासाठी प्रमाणीकरण प्रवाह हवा असेल तर **सविस्तर अंमलबजावणी** वापरा.

AI ने विचारल्यास प्रथम CMS पत्ता, टोकन ठेवणाऱ्या environment variable चे नाव आणि `secure` डेटातील वापरकर्ता माहिती सांगा.
