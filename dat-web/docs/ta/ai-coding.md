# AI வைப் கோடிங்

தற்போதைய திட்டம் மற்றும் நீங்கள் விரும்பும் செயல்பாட்டை AI-க்குத் தெரிவித்தால் DAT-ஐ எளிதாகப் பயன்படுத்தலாம். கீழேயுள்ள எடுத்துக்காட்டில் உள்ள முகவரி மற்றும் சூழல் மாறிப் பெயர்களை மட்டும் உங்கள் திட்டத்திற்கேற்ப மாற்றிப் பயன்படுத்தவும்.

## எளிமையாக செயல்படுத்துதல்

அடிப்படைக் கட்டமைப்பை விரைவாக உருவாக்க விரும்பும்போது பயன்படுத்தும் கோரிக்கை இது.

```text
நான் Kotlin மற்றும் Spring Boot பயன்படுத்துகிறேன்.
Spring Security-ல் DAT அங்கீகரிப்பைச் சேர்க்கவும்.

முதலில் https://dat.saro.me/llms.txt ஐப் படித்து,
DAT விவரக்குறிப்பையும் அதிகாரப்பூர்வ நூலகத்தின் பயன்பாட்டையும் சரிபார்க்கவும்.

Authorization தலைப்பிலுள்ள Bearer டோக்கனைச் சரிபார்த்து,
அங்கீகரிப்பு வெற்றியடைந்தால் SecurityContext-ல் பயனர் தகவலை வைக்கவும்.

இந்தச் சேவை DAT-ஐ வழங்காது; சரிபார்ப்பு மட்டுமே செய்யும்.
DAT CMS-லிருந்து சரிபார்ப்பு-மட்டுமான சான்றிதழ்களைப் பெற வேண்டும்.

CMS சேவையக முகவரி மற்றும் டோக்கன் அமைப்பை முதலில் திட்டத்தில் தேடவும்;
கண்டுபிடிக்க முடியாவிட்டால் என்னிடம் கேட்கவும். தன்னிச்சையான மதிப்புகளை உருவாக்க வேண்டாம்.

அதிகாரப்பூர்வ Java/Kotlin DAT நூலகத்தைப் பயன்படுத்தி,
ஏற்கனவேயுள்ள திட்டக் கட்டமைப்பு மற்றும் கோடிங் பாணிக்கு ஏற்ப செயல்படுத்தவும்.
```

## விரிவாக செயல்படுத்துதல்

அங்கீகரிப்பு முறையையும் பிழை கையாளுதலையும் துல்லியமாகக் குறிப்பிட விரும்பும்போது பயன்படுத்தும் கோரிக்கை இது.

```text
இந்தத் திட்டம் Kotlin, Spring Boot மற்றும் Spring Security-ஐப் பயன்படுத்துகிறது.
தற்போதைய பாதுகாப்பு அமைப்பைச் சரிபார்த்த பின் DAT அங்கீகரிப்பைச் சேர்க்கவும்.

முதலில் https://dat.saro.me/llms.txt ஐப் படித்து,
DAT விவரக்குறிப்பு, சான்றிதழ் ஒத்திசைவு முறை மற்றும் அதிகாரப்பூர்வ நூலக API-ஐச் சரிபார்க்கவும்.

செயல்படுத்தல் நிபந்தனைகள்:

- Authorization: Bearer தலைப்பிலிருந்து DAT-ஐப் படிக்கவும்.
- DAT இல்லாவிட்டால் அநாமதேயக் கோரிக்கையாகத் தொடரவும்.
- DAT தவறானதாக அல்லது காலாவதியானதாக இருந்தால் 401 பதிலை அனுப்பவும்.
- சரிபார்ப்பு வெற்றியடைந்தால் பயனர் ID மற்றும் அனுமதிகளை SecurityContext-ல் வைக்கவும்.
- பொதுவாக வெளிப்படக்கூடிய மதிப்புகளை மட்டும் plain-லிருந்து படிக்கவும்.
- பயனர் ID மற்றும் அனுமதிகளைச் சரிபார்க்கப்பட்ட secure தரவிலிருந்து படிக்கவும்.
- இந்தச் சேவை சரிபார்ப்பு-மட்டுமானதால் DAT CMS-ன் verify-only சான்றிதழ்களைப் பயன்படுத்தவும்.
- CMS முகவரி மற்றும் டோக்கனை சூழல் மாறிகளாகப் பெறவும்.
- தொடக்கத்தில் சான்றிதழ் ஒத்திசைவு தோல்வியடைந்தால் பயன்பாட்டின் தொடக்கத்தையும் தோல்வியடையச் செய்யவும்.
- இயங்கும்போது சான்றிதழ்களைத் தானாகப் புதுப்பித்து, முடிக்கும்போது மேலாளரை மூடவும்.
- பிழைச் செய்திக்குப் பதிலாக DAT பிழைக் குறியீட்டால் தோல்வியின் காரணத்தை வேறுபடுத்தவும்.
- DAT-ன் மூல உரை, CMS டோக்கன் அல்லது தனிப்பட்ட தகவலை பதிவுகளில் சேமிக்க வேண்டாம்.

முதலில் திட்டத்தின் Spring Security அமைப்பையும் பயனர்/அனுமதிக் கட்டமைப்பையும் சரிபார்க்கவும்.
CMS முகவரி, டோக்கன் சூழல் மாறிகள் அல்லது secure தரவு வடிவம் தெரியாவிட்டால் செயல்படுத்துவதற்கு முன் கேட்கவும்.
அதிகாரப்பூர்வ Java/Kotlin DAT நூலகத்தின் பொது API-களை மட்டும் பயன்படுத்தவும்.

குறிமுறையை மாற்றுவதற்கு முன் அங்கீகரிப்பு ஓட்டத்தையும் மாற்றப்படும் கோப்புகளையும் சுருக்கமாக விளக்கவும்.
```

## எந்த எடுத்துக்காட்டைத் தேர்ந்தெடுப்பது?

- முதலில் இயங்கும் குறிமுறையை உருவாக்கிப் பார்க்க விரும்பினால் **எளிமையாக செயல்படுத்துதல்** என்பதைப் பயன்படுத்தவும்.
- உற்பத்திச் சூழலுக்கான அங்கீகரிப்பு ஓட்டம் தேவையானால் **விரிவாக செயல்படுத்துதல்** என்பதைப் பயன்படுத்தவும்.

AI கேள்வி கேட்டால், CMS முகவரி, டோக்கனை வைத்திருக்கும் சூழல் மாறியின் பெயர் மற்றும் `secure` தரவில் வைக்கப்படும் பயனர் தகவலை முதலில் பதிலளிக்கவும்.
