# AI-вайб-кодинг

Расскажите AI о текущем проекте и желаемом поведении, чтобы упростить интеграцию DAT. В примерах ниже измените только URL и имена environment variables в соответствии со своим проектом.

## Простая реализация

Используйте этот prompt, чтобы быстро создать базовую структуру.

```text
Я использую Kotlin и Spring Boot.
Добавь DAT authentication в Spring Security.

Сначала прочитай https://dat.saro.me/llms.txt и изучи
спецификацию DAT и документацию официальной библиотеки.

Проверяй Bearer token из заголовка Authorization,
а при успешной authentication помещай информацию о пользователе в SecurityContext.

Этот сервер не выпускает DAT, а только проверяет их.
Он должен получать сертификаты verify-only из DAT CMS.

Сначала найди в проекте настройки URL сервера CMS и токена.
Если их нет, спроси меня. Не придумывай значения.

Используй официальную библиотеку DAT для Java/Kotlin
и следуй существующей структуре проекта и стилю кода.
```

## Подробная реализация

Используйте этот prompt, чтобы точно определить поток аутентификации и обработку ошибок.

```text
Этот проект использует Kotlin, Spring Boot и Spring Security.
Изучи текущую конфигурацию безопасности, затем добавь DAT authentication.

Сначала прочитай https://dat.saro.me/llms.txt и изучи
спецификацию DAT, синхронизацию сертификатов и API официальной библиотеки.

Реализуй следующие требования.

- Читай DAT из заголовка Authorization: Bearer.
- Если DAT отсутствует, продолжай как с анонимным запросом.
- Если DAT недействителен или истёк, отвечай 401.
- После успешной проверки помести ID пользователя и разрешения в SecurityContext.
- Из plain читай только значения, которые безопасно раскрывать.
- ID пользователя и разрешения читай из проверенных данных secure.
- Этот сервер работает в режиме verify-only, поэтому используй сертификаты verify-only из DAT CMS.
- Читай URL CMS и токен из environment variables.
- Если синхронизация сертификатов при запуске не удалась, заверши запуск приложения с ошибкой.
- Автоматически обновляй сертификаты во время работы и закрывай manager при завершении.
- Различай причины сбоев по DAT error codes, а не по сообщениям.
- Не записывай в лог исходный DAT, токен CMS или персональные данные.

Сначала проверь конфигурацию Spring Security и модель пользователей/разрешений проекта.
Если URL CMS, environment variable токена или формат данных secure неясны, спроси до реализации.
Используй только public API официальной библиотеки DAT для Java/Kotlin.

Перед изменением кода кратко объясни поток аутентификации и перечисли изменяемые файлы.
```

## Какой пример выбрать?

- Выберите **Простую реализацию**, если сначала нужен работающий код.
- Выберите **Подробную реализацию**, если нужен поток аутентификации для production environment.

Если AI задаст вопросы, сначала укажите URL CMS, environment variable с токеном и информацию о пользователе, хранящуюся в `secure`.
