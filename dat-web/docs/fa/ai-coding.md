# کدنویسی احساسی با هوش مصنوعی

با توضیح پروژه فعلی و رفتار موردنظر برای هوش مصنوعی، می‌توانید DAT را آسان‌تر به‌کار بگیرید. در نمونه‌های زیر، فقط نشانی و نام متغیرهای محیطی را متناسب با پروژه خود تغییر دهید.

## پیاده‌سازی ساده

این درخواست زمانی مناسب است که می‌خواهید ساختار پایه را سریع بسازید.

```text
از Kotlin و Spring Boot استفاده می‌کنم.
احراز هویت DAT را به Spring Security اضافه کن.

ابتدا https://dat.saro.me/llms.txt را بخوان و
مشخصات DAT و روش استفاده از کتابخانه رسمی را بررسی کن.

توکن Bearer در هدر Authorization را راستی‌آزمایی کن و
در صورت موفقیت احراز هویت، اطلاعات کاربر را در SecurityContext قرار بده.

این سرور DAT صادر نمی‌کند و فقط آن را راستی‌آزمایی می‌کند.
باید گواهی فقط راستی‌آزمایی را از DAT CMS دریافت کند.

ابتدا نشانی سرور CMS و تنظیمات توکن را در پروژه پیدا کن و
اگر پیدا نشد از من بپرس. مقدار فرضی نساز.

از کتابخانه رسمی Java/Kotlin DAT استفاده کن و
پیاده‌سازی را با ساختار و سبک کدنویسی فعلی پروژه هماهنگ کن.
```

## پیاده‌سازی دقیق

این درخواست زمانی مناسب است که می‌خواهید روش احراز هویت و پردازش خطا را دقیقاً مشخص کنید.

```text
این پروژه از Kotlin، Spring Boot و Spring Security استفاده می‌کند.
پس از بررسی تنظیمات امنیتی فعلی، احراز هویت DAT را اضافه کن.

ابتدا https://dat.saro.me/llms.txt را بخوان و
مشخصات DAT، روش همگام‌سازی گواهی و API کتابخانه رسمی را بررسی کن.

شرایط پیاده‌سازی به شرح زیر است.

- DAT را از هدر Authorization: Bearer بخوان.
- اگر DAT وجود نداشت، درخواست را به‌عنوان ناشناس ادامه بده.
- اگر DAT نادرست یا منقضی بود، با 401 پاسخ بده.
- در صورت موفقیت راستی‌آزمایی، شناسه کاربر و مجوزها را در SecurityContext قرار بده.
- فقط مقادیری را از plain بخوان که عمومی بودنشان اشکالی ندارد.
- شناسه کاربر و مجوزها را از داده secure راستی‌آزمایی‌شده بخوان.
- این سرور فقط راستی‌آزمایی می‌کند، پس از گواهی verify-only متعلق به DAT CMS استفاده کن.
- نشانی CMS و توکن را از متغیرهای محیطی بگیر.
- اگر همگام‌سازی گواهی هنگام راه‌اندازی ناموفق بود، راه‌اندازی برنامه را هم ناموفق کن.
- هنگام اجرا گواهی‌ها را خودکار به‌روز کن و هنگام خاتمه، مدیر را ببند.
- علت شکست را با کد خطای DAT تشخیص بده، نه متن پیام خطا.
- متن اصلی DAT، توکن CMS و اطلاعات شخصی را در لاگ ثبت نکن.

ابتدا تنظیمات Spring Security و ساختار کاربر و مجوز پروژه را بررسی کن.
اگر نشانی CMS، متغیرهای محیطی توکن یا قالب داده secure مشخص نیست، پیش از پیاده‌سازی بپرس.
فقط از API عمومی کتابخانه رسمی Java/Kotlin DAT استفاده کن.

پیش از تغییر کد، روند احراز هویت و فایل‌هایی را که تغییر می‌کنند کوتاه توضیح بده.
```

## کدام نمونه را انتخاب کنم؟

- اگر می‌خواهید ابتدا کدی بسازید که اجرا شود، از **پیاده‌سازی ساده** استفاده کنید.
- اگر به روند احراز هویت مناسب محیط عملیاتی نیاز دارید، از **پیاده‌سازی دقیق** استفاده کنید.

وقتی هوش مصنوعی پرسشی می‌پرسد، ابتدا نشانی CMS، نام متغیر محیطی حاوی توکن و اطلاعات کاربری قرارگرفته در داده `secure` را پاسخ دهید.
