# การเขียนโค้ดแบบ Vibe ด้วย AI

คุณสามารถนำ DAT ไปใช้ได้ง่ายขึ้นด้วยการบอก AI เกี่ยวกับโปรเจกต์ปัจจุบันและพฤติกรรมที่ต้องการ ให้เปลี่ยนเฉพาะที่อยู่และชื่อตัวแปรสภาพแวดล้อมในตัวอย่างด้านล่างให้ตรงกับโปรเจกต์แล้วนำไปใช้

## นำไปใช้แบบง่าย

คำขอนี้ใช้เมื่อต้องการสร้างโครงสร้างพื้นฐานอย่างรวดเร็ว

```text
ฉันกำลังใช้ Kotlin และ Spring Boot
ช่วยเพิ่มการยืนยันตัวตน DAT ให้ Spring Security

ก่อนอื่นให้อ่าน https://dat.saro.me/llms.txt
แล้วตรวจสอบข้อกำหนด DAT และวิธีใช้ไลบรารีทางการ

ตรวจสอบ Bearer token ในส่วนหัว Authorization
และเมื่อยืนยันตัวตนสำเร็จ ให้ใส่ข้อมูลผู้ใช้ลงใน SecurityContext

เซิร์ฟเวอร์นี้ไม่ออก DAT และทำเฉพาะการตรวจสอบ
จึงต้องรับใบรับรองสำหรับตรวจสอบเท่านั้นจาก DAT CMS

ให้ค้นหาการตั้งค่าที่อยู่และโทเค็นของเซิร์ฟเวอร์ CMS ในโปรเจกต์ก่อน
หากหาไม่พบให้ถามฉัน อย่าสร้างค่าขึ้นมาเอง

ใช้ไลบรารี DAT ทางการสำหรับ Java/Kotlin
และนำไปใช้ให้เข้ากับโครงสร้างและรูปแบบการเขียนโค้ดที่มีอยู่ในโปรเจกต์
```

## นำไปใช้อย่างละเอียด

คำขอนี้ใช้เมื่อต้องการระบุวิธียืนยันตัวตนและการจัดการข้อผิดพลาดอย่างแม่นยำ

```text
โปรเจกต์นี้ใช้ Kotlin, Spring Boot และ Spring Security
ให้ตรวจสอบการตั้งค่าความปลอดภัยปัจจุบันแล้วจึงเพิ่มการยืนยันตัวตน DAT

ก่อนอื่นให้อ่าน https://dat.saro.me/llms.txt
แล้วตรวจสอบข้อกำหนด DAT วิธีซิงค์ใบรับรอง และ API ของไลบรารีทางการ

เงื่อนไขในการนำไปใช้มีดังนี้

- อ่าน DAT จากส่วนหัว Authorization: Bearer
- หากไม่มี DAT ให้ดำเนินการต่อในฐานะคำขอแบบไม่ระบุตัวตน
- หาก DAT ไม่ถูกต้องหรือหมดอายุ ให้ตอบกลับด้วย 401
- เมื่อยืนยันตัวตนสำเร็จ ให้ใส่ ID ผู้ใช้และสิทธิ์ลงใน SecurityContext
- อ่านจาก plain เฉพาะค่าที่สามารถเปิดเผยสู่สาธารณะได้
- อ่าน ID ผู้ใช้และสิทธิ์จากข้อมูล secure ที่ผ่านการตรวจสอบแล้ว
- เซิร์ฟเวอร์นี้ใช้สำหรับตรวจสอบเท่านั้น จึงให้ใช้ใบรับรอง verify-only ของ DAT CMS
- รับที่อยู่ CMS และโทเค็นผ่านตัวแปรสภาพแวดล้อม
- หากซิงค์ใบรับรองล้มเหลวตอนเริ่มต้น ให้การเริ่มต้นแอปพลิเคชันล้มเหลวด้วย
- ระหว่างรันให้อัปเดตใบรับรองโดยอัตโนมัติ และเมื่อปิดระบบให้ปิดตัวจัดการ
- จำแนกสาเหตุความล้มเหลวด้วยรหัสข้อผิดพลาด DAT ไม่ใช่ข้อความข้อผิดพลาด
- ห้ามบันทึก DAT ต้นฉบับ โทเค็น CMS หรือข้อมูลส่วนบุคคลลงในล็อก

ก่อนอื่นให้ตรวจสอบการตั้งค่า Spring Security และโครงสร้างผู้ใช้·สิทธิ์ของโปรเจกต์
หากไม่ทราบที่อยู่ CMS ตัวแปรสภาพแวดล้อมของโทเค็น หรือรูปแบบข้อมูล secure ให้ถามก่อนลงมือทำ
ใช้เฉพาะ API สาธารณะของไลบรารี DAT ทางการสำหรับ Java/Kotlin

ก่อนแก้ไขโค้ด ให้อธิบายขั้นตอนการยืนยันตัวตนและไฟล์ที่จะแก้ไขโดยสั้นๆ
```

## ควรเลือกตัวอย่างใด?

- หากต้องการสร้างโค้ดที่รันได้ก่อน ให้ใช้ **นำไปใช้แบบง่าย**
- หากต้องการขั้นตอนการยืนยันตัวตนสำหรับสภาพแวดล้อมโปรดักชัน ให้ใช้ **นำไปใช้อย่างละเอียด**

เมื่อ AI ถาม ให้ตอบเรื่องที่อยู่ CMS ชื่อตัวแปรสภาพแวดล้อมที่เก็บโทเค็น และข้อมูลผู้ใช้ที่จะใส่ในข้อมูล `secure` ก่อน
