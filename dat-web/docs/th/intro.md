# DAT คืออะไร?

DAT (Distributed Access Token) คือข้อกำหนดโทเค็นการเข้าถึงที่บริการออกโทเค็นและบริการตรวจสอบใช้ใบรับรองชุดเดียวกัน เมื่อตรวจสอบไม่จำเป็นต้องส่งคำขอไปยังบริการออกโทเค็นหรือที่เก็บเซสชันศูนย์กลางอีกครั้ง จึงสามารถส่งต่อผลการยืนยันตัวตนพร้อมลดการผูกติดระหว่างบริการได้

## ส่วนประกอบ

### DAT

คือสตริงที่ผู้ใช้หรือบริการส่งมาพร้อมกับคำขอ ประกอบด้วยเวลาหมดอายุและ ID ใบรับรอง และสามารถเก็บทั้งข้อมูลสาธารณะและข้อมูลเข้ารหัสไว้ด้วยกัน

### ใบรับรอง

เก็บอัลกอริทึม คีย์ และช่วงเวลาที่จำเป็นต่อการสร้างและตรวจสอบ DAT `cid` ซึ่งเป็น ID ใบรับรองจะไม่เปลี่ยนแปลง และเมื่อเปลี่ยนคีย์จะใช้ `cid` ใหม่

### ตัวจัดการ

ตัวจัดการของไลบรารีไคลเอนต์จะเก็บใบรับรอง สร้าง DAT ด้วยใบรับรองที่สามารถออกได้ในปัจจุบัน และตรวจสอบด้วยใบรับรองที่ตรงกับ `cid` ของ DAT

### DAT CMS

เป็นเซิร์ฟเวอร์ทางเลือกที่สร้างและเก็บรักษาใบรับรอง แล้วส่งให้บริการ สามารถมอบใบรับรองแบบเต็มให้บริการออกโทเค็น และใบรับรองสำหรับตรวจสอบเท่านั้นให้บริการที่ทำเฉพาะการตรวจสอบได้

บริการออกโทเค็นกำหนดข้อมูล `plain` และ `secure` และสร้าง DAT บริการตรวจสอบจะตรวจเวลาหมดอายุ ลายเซ็น และข้อความเข้ารหัส แล้วจึงส่งพื้นที่ข้อมูลทั้งสองให้แอปพลิเคชัน `plain` ได้รับการลงนามแต่ไม่ได้เข้ารหัส ดังนั้นห้ามใส่ความลับหรือข้อมูลส่วนบุคคลลงไป

## เหตุผลที่ยังตรวจสอบได้แม้ใบรับรองจะเปลี่ยน

เมื่อใบรับรองใหม่สามารถออกได้ DAT ที่ออกหลังจากนั้นจะใช้ `cid` ใหม่ ใบรับรองเดิมยังคงอยู่สำหรับการตรวจสอบจนกว่า TTL ของ DAT ที่ออกไปแล้วจะสิ้นสุด จึงสามารถจัดการทั้งการเปลี่ยนคีย์และระยะเวลาตรวจสอบโทเค็นเดิมไปพร้อมกันได้

## เหมาะกับสภาพแวดล้อมแบบใด

- สภาพแวดล้อมที่บริการคนละตัวรับผิดชอบการยืนยันตัวตนและฟังก์ชันจริง
- สภาพแวดล้อมที่รันไทม์หลายชนิดออกหรือตรวจสอบโทเค็นเดียวกัน
- สภาพแวดล้อมที่ต้องการส่งต่อข้อมูลสิทธิ์อายุสั้นโดยไม่ค้นหาเซสชันจากศูนย์กลาง
- สภาพแวดล้อมที่ต้องแยกเก็บข้อมูลกำหนดเส้นทางสาธารณะและข้อมูลที่ต้องป้องกันไว้ในโทเค็นเดียวกัน

DAT ไม่ได้กำหนนโยบายสิทธิ์เอง ข้อเท็จจริงที่ว่า DAT ใช้งานได้ และการตัดสินใจของแอปพลิเคชันว่าจะอนุญาตคำขอนั้นหรือไม่ เป็นคนละเรื่องกัน
